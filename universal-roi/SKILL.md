# 万事万物 ROI 决策计算器

把一个 Idea 转化为可查证、可计算、可比较、可试验的决策。默认中文，随用户语言调整。目标是帮助用户决定是否行动、如何行动、何时停止；不承诺收益，不把所有价值强行换算成钱。

用户可以只提供一个想法。先利用已有信息开展分析；材料不足时交付有条件的初评与关键缺口，不把问卷变成开工门槛。分析深度随资金规模、不可逆性和不确定性调整；用户要求完整分析时覆盖下文所有维度。

## 1. 定义要做的决定

从对话和材料提取：
- **想法与机制**：打算做什么，为谁解决什么，投入如何转化为结果。
- **目标与门槛**：用户到底想获得什么；可衡量的成功标准、优先级、必须满足的底线。区分用户、客户、合作方等主体的收益与代价。
- **资源与边界**：可用现金、每周时间、技能、渠道、团队、现有资产、地区、货币、截止日期、评估期、最大可承受损失。
- **比较基准**：继续现状/什么都不做的真实后果；另一个可行方案；条件允许时增加小规模试验方案。现状也可能有持续支出、流失和机会损失。

只追问最可能改变结论的缺失信息，通常一次不超过三个问题；同时继续不依赖答案的研究。不可推断个人风险承受力、健康状态或关系价值。无答案的字段保留“未知”，可提出明确标注的假设区间。

开头用几句话复述决策、基准、期限与关键约束。多个目标有冲突时说明取舍；不要替用户虚构权重。

## 2. 查证支撑结论的数据

先列出会改变决定的证据问题，再开展可用工具支持的联网搜索。网络不是“全网穷尽检索”；说明搜索范围与重大缺口。

- 搜索需求/真实使用、价格与全部收费、可比案例与失败案例、实施条件、时间成本、规则与替代方案，按具体想法选择相关项。
- 对时效性强或影响大的参数查当前资料，优先官方定价与文档、政府规则、原始研究、公开财报和可验证的一手数据。商业宣传与论坛是线索，注明偏差。
- 对决定结论的参数尽量交叉验证；无法取得独立证据则明确单一来源。不要把同一报道的转载视为独立证据。
- 记录来源链接、数据时点、适用地区/人群、计量单位、原始值及采用区间。说明样本是否与用户可比、是否存在幸存者偏差。
- 用户数据、网络事实、模型推导、暂定假设分别标记。冲突的数据解释口径差异或保留区间，不挑选最乐观数字。
- 只搜索研究所需的概括信息，不把用户的身份信息、机密商业数据或完整私有材料直接放进公开查询。

不能联网时明确说明“尚未联网验证”，只给基于现有材料的条件分析；不伪造引用或宣称已经搜索。来源在对应论断附近给出可点击链接。

当高影响问题得到足够证据、新增搜索不再改变参数区间时结束检索；未解决的问题进入验证清单。联网和长篇推理本身不等于证据充分。

## 3. 建立收益、成本与条件账本

沿“投入 → 活动 → 直接产出 → 最终结果”画出文字因果链，逐段标记依赖、延迟、成功条件与可能失效处。区分可控制的行动和无法控制的外部结果。

**收益**：现金收入、可实际减少的现金支出、可支配时间、技能与资产、选择权、健康/体验/关系等。每项写明谁获得、何时兑现、持续多久、证据与限制。

**代价**：启动、持续运营、维护返工、获客、交付、工具订阅、手续费、税费、资金占用、退出及恢复成本；时间、注意力、情绪压力、机会成本、关系与声誉影响。按适用性选择，不套用无关风险。

**隐藏条件**：用 [条件与领域检查表](references/decision-checks.md) 检查与任务相关的条目。把关键条件写成“条件 → 若不成立的后果 → 验证方法 → 成本/耗时 → 谁来解决”。至少区分必要前提、可协商条件和外部依赖。

计量要求：
- 使用相对于比较基准的增量，沉没成本另列，不用“已经投了很多”证明应该继续。
- 现金收益、可估价非现金收益、无法合理货币化的价值分栏；节省时间仅在能减少支出或产生有证据的增量收入时记作现金。
- 不重复计入同一效应：已计收入损失不再加同一机会成本；已计付薪工时不再加相同工时估值；残值、订阅和资金占用注意重复。
- 机会成本基于实际可行的次优选择；无可靠时薪则报告小时数与估值敏感性，不擅自乘一个“市场平均时薪”。
- 非金钱目标用自然单位和底线评估，例如每周多出几小时、能力达标时间、可接受压力。多准则评分只有在权重明确且解释尺度时使用，不用一个神秘总分掩盖取舍。

## 4. 计算与情景分析

存在可量化现金流时，读 [计算口径与脚本输入](references/calculation.md)，使用 `scripts/roi_calculator.py` 或同等可复算代码计算。保留输入和公式，让读者能替换参数复算。没有足够数字则给公式、区间或临界值，不填造数字凑 ROI。

主要财务指标按适用性给出：净现金收益、明确分母的现金 ROI、资金缺口、回本时间；跨期决策给 NPV 并说明折现率；经营项目给单位经济性与盈亏平衡点。资金峰值/本金回收不等于成本，利润不等于现金流。

建立内部一致的情景，通常包括：
1. **最好合理情景**：有证据或能力上限支持的乐观结果与达成条件；不是理论最大值。
2. **基准情景**：最可辩护的规划假设；没有概率依据时不称为“最可能”。
3. **最坏合理情景**：需求不足、成本超支、延期、失败与退出等相关冲击下的结果。
4. **尾部灾难/不可逆损失**：仅在实质相关时单列。合理悲观情景不是绝对损失下限；损失无法封顶时直说。

各情景使用相同基准、期限、币种和成本范围；改变关键驱动而不是把结果任意乘 0.5 或 2。遵守相关性、产能和时间约束，例如增长也可能增加获客、交付、维护费用。

情景表列出关键假设、收益、现金支出、非现金代价、净收益/ROI（适用时）、回本、资金峰值与结果条件。不要在看似精确的概率下隐藏主观猜测。仅当情景互斥且完备、概率有依据或用户明确提供时计算概率加权值；同时保留损失和尾部风险。模拟或 P10/P90 需要说明分布、相关性和估计依据，不能把三个情景当作统计分位数。

分析最能改变结论的 2–5 个变量，报告“什么值会让建议反转”，并检查组合冲击。不能解析求解时使用扫描/二分等可复算方法，说明测试范围。没有单调性时不能宣称唯一临界值。

## 5. 给出决策与行动路径

先检查底线、现金与时间可行性，再比较收益；正 ROI 也可能因承受不了资金缺口、耗时或不可逆风险而不可行。

给出“行动 / 先小试 / 补证据后决定 / 暂不做”之一或有条件的选择，标明结论强度和依据。明确哪些条件会改变建议，不用模糊的“视情况而定”结束。

行动方案应说明：
- 第一步与最小验证试验：验证哪个决定性假设、采用什么方法。
- 各阶段的交付物、责任人/所需能力、前置依赖、时间与现金预算。
- 通过、扩大、暂停与退出条件：可观察指标、检查时间、可承受损失；预算和门槛未获用户定义时标成建议值。
- 试验结果如何更新假设和重新计算。补充研究只有在可能改变决定且价值超过成本时继续；不默认精算信息价值。

“建议执行”不意味着已获准购买、交易、联系他人或更改外部系统。此 Skill 默认交付分析与行动方案，执行遵循用户另行给出的授权范围。

## 6. 输出为可直接决策的报告

参照 [报告骨架](references/report-template.md)，小问题可压缩合并，但保留结论、收益与全部代价、情景、隐藏条件、下一步和证据缺口。完整分析附关键参数、公式与来源，禁止只给一段笼统建议。

交付前自查：基准是否一致；币种/时点/单位是否明确；现金与非现金是否分开；是否漏掉失败和退出；概率是否有依据；是否重复计算；用户约束是否被满足；来源是否支撑实际论断；建议能否通过明确条件被证伪。

可用调用示例：
> 用这个 Skill 评估：我想用 AI 做一个副业，每周能投入 8 小时，预算 5000 元，希望 6 个月内产生收入。帮我查证需求和成本，分析能得到什么、最好和最坏结果、隐藏条件，并给出最低成本的验证步骤。

同样适用于购买设备、学习技能、换工作、建设 Agent、搬家或生活习惯；根据目标选择指标，避免把生活选择强行包装成金融投资。
